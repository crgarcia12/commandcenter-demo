Command Center architecture

The docs say Command Center needs a pre-provisioned dedicated modernization repository; it does not automatically create it.

Run Command Center locally

npm install -g @github/copilot
gh auth login
gh repo create <org>/<repo> --private

# Enable Command Center
# ~/.modernize/config.json
{
  "feature_flags": { "command_center": true }
}

modernize cc init --repo https://github.com/<org>/<repo>
modernize cc serve

The dedicated modernization repo must already exist. Optional serve flags include --port <n> and --no-open.

Single-user or operator-hosted

Single-user

Localhost, reuses the CLI GitHub token, good for local testing and individual use.

Multi-user

Hosted behind a reverse proxy with GitHub OAuth sign-ins and a central configuration.

The guide says GitHub OAuth App is required for multi-user mode; GitHub Apps are not interchangeable.

Multi-user setup has explicit operator work

Infrastructure

Stable URL, TLS-terminating reverse proxy, X-Forwarded-Proto: https, host and port in config.

OAuth app

Classic GitHub OAuth App with callback /auth/callback; record client ID and secret securely.

The multi-user block activates multi-user workflows; config is parsed at startup and changes require restart.

modernize cc app register --name <appname> --app-repo <repo-url>

The Zava demo scales this pattern across the Java and .NET app portfolio.

Create a project, add apps, then assess

modernize cc project create \
  --name "BUILD2026" \
  --goal "modernize Zava app and deploy to Azure"

modernize cc project app add --project BUILD2026 --app <appname>
modernize cc assess --project BUILD2026 \
  --delegate cloud \
  --assess-config ./assessment-config.yaml

The guide also says assessment can be run visually from Command Center after creating a project and selecting apps.

A practical demo flow

Use Command Center as the connective tissue: portfolio view, plan creation, issue/PR handoff, and project activity.

Workstream 1

Java path: Struts to Spring Boot

The demo storyline uses ZavaPay Gateway to rewrite a Struts application toward Java 21 and Spring Boot in another directory.

  • Introduce non-compliant logging and messaging for the custom-skill demo.
  • Execute from Command Center so status ties back to the project.
  • Follow the generated GitHub issue in VS Code.
  • Close the issue when rewrite is complete.

Workstream 2

.NET path: Web Forms to Blazor + Aspire

The storyline uses ZavaLoan Portal to show Web Forms migration, Blazor conversion, and Aspire enablement.

  • Open the folder in VS Code or the solution in Visual Studio.
  • Use the GitHub Copilot modernization for .NET experience.
  • Prompt for a .NET 10 upgrade and Web Forms to Blazor migration.
  • Prompt Add Aspire after the Blazor migration.

Guardrails and requirements

  • Latest Copilot CLI installed globally: npm install -g @github/copilot.
  • Git installed and available on PATH.
  • Eligible GitHub Copilot plan: Free, Pro, Pro+, Business, or Enterprise, per guide.
  • GitHub CLI installed, verified, and authenticated for Command Center setup.
  • Dedicated modernization repository created before modernize cc init.

Things not to gloss over

Command Center does not automatically create the dedicated modernization repository. Multi-user mode needs a GitHub OAuth App and careful secret handling.

Feature flags Repo permissions OAuth callback URLs Rulebook ownership

Suggested next steps

  1. Pick a small portfolio and create the dedicated modernization repo.
  2. Enable Command Center and register apps from a manifest.
  3. Run assessments before choosing an execution mode.
  4. Write one rulebook and one custom skill that reflect real team standards.
  5. Use Command Center to monitor progress and attention items.
